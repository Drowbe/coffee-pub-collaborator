# Documents Architecture

**Audience:** developers working on the Documents module (`modules/documents/`), or building another module on its shape.

The module is a bundled module that runs in the page. It keeps each space's documents in the module's storage, scope `space`. The user's view is [userguide-documents](../userguides/userguide-documents.md). Version 0.11.31. Written from the code and the plans ([plan-documents-rich-editor](../plans/plan-documents-rich-editor.md), [plan-documents-paper-layout](../plans/plan-documents-paper-layout.md), [plan-documents-coediting](../plans/plan-documents-coediting.md)); the module's tests were not rerun for this document.

## Files

`src/documents-lib-*.js` hold the rules and have no page and no host, so another module can reuse them: `a-records` (cleaning the stored records), `b-chunks` (splitting and joining the text), `c-lock` (the lock rules), `d-reader` (Markdown to a plain description, then to DOM), `e-export`, `f-format` (the formatting bar's text changes), `g-save` (the save pace), `h-view` (zoom and list views), `i-tags`, `j-resync`, and since 0.7: `k-editor` (the one small object both editors sit behind), `l-schema` (the rich editor's document model), `m-parse` (Markdown to the reader's description to that model), `n-serialise` and `o-write` (the model back to Markdown, block by block), `p-rich-editor` (the rich editor), `q-rich-rules` (typing shortcuts and the bar's states), `r-rich-link` (the Link button, through `host.ui.prompt`), `s-pages` (Paper pages in reading) and `t-editor-pages` (page spacers in the rich editor). Since 0.11.15 (co-editing, used only with the `coediting` switch on, see "Co-editing"): `t-coedit-gate`, `u-coedit-sync`, `v-coedit-save`, `w-coedit-snapshot` and `x-coedit-meta`. `u-output` (0.11.18) holds the rules for Print, Save as Markdown file and Open Markdown file. `documents-lib-0-prosemirror.js` is the vendored editor library (since 0.11.13 it also holds Yjs, `y-prosemirror`, `lib0` and `isomorphic.js`; `THIRD-PARTY.md` lists them). `documents-lib-0-marked.js` is the vendored Markdown lexer. `documents.js` is the page; `documents.html` and `documents.css` are its markup and styles. The tests are `test/` and `tools/check-documents-lib.mjs`.

## Stored keys

| Key | Holds |
|---|---|
| `doc:<id>` | The small record: `title` (up to 120), `rev`, `chunks`, `size`, `excerpt`, `preview`, `paper` (the page colour id), `layout` (`fluid` or `paper`), `pageSize` (`letter` or `a4`), `pageNumbers`, who made and last edited it. |
| `text:<id>:<c>` | A chunk of the text. A document is at most 150,000 characters in at most 6 chunks, each chunk record under 48,000 characters of serialized JSON, measured. |
| `_lock:<id>` | The edit lock: `holder`, `name`, `at`, `seq`. |
| `_trash:<id>` | A deleted document (its small record and the time), kept for 7 days. |
| `tags:<id>` | The tag ids of the document, in a record of their own so tagging never competes with a text save. |
| `ydoc:<id>`, `ydoc:<id>:<n>`, `ydoc:<id>:seed`, `ydoc:<id>:w:<person>` | Only with `coediting` on: the stored copy of a shared document's state (header, chunks), the seed marker and a person's one-edit-window key. See "Co-editing". |

The record `doc:<id>` also carries `textRev`, a counter every co-editing save raises (0.11.23); a record made by the older saves has none.

Every record is cleaned on reading as well as on writing: a wrong type, unknown fields, control and direction characters and bad ids are dropped; a record that does not clean is shown as unreadable.

## Saving and the lock

An edit takes the lock with compare-and-set (`_lock:<id>`). The editor renews it every 10 seconds (`beat`); a lock nobody has seen change for 35 seconds (`stale`, on the reader's own clock) counts as free, and an old lock read at load waits 12 seconds for a change before it counts as stale. A save runs 3 seconds after the last key, at most 200 a minute (the rest of the 240 writes a minute the module is allowed is for the lock). It writes the changed text chunks first, then the small record under the version it read: that write is the commit, so a save that dies halfway leaves the old text readable. A save that finds the record changed by someone else stops the editing and keeps the person's text on the screen.

## Hearing changes

The page listens to `change`, so a reader sees a save as it lands. On `host.on('reconnected')` it reads the keys again (`resyncDocs`, `j-resync`) and merges. The list view and zoom are kept in the browser.

## Tags

`"tags": true` in `module.json`. The page uses `host.tags` (list, picker, chip, `filterOptions`) and hears `tags` ([api-module-sdk](../api/api-module-sdk.md), "Shared tags"). A document's ids sit in `tags:<id>`; a deleted tag's id is skipped when drawn.

## The rich editor and Paper

**Markdown stays what is stored.** The rich editor (ProseMirror, vendored; 16 packages in one file, see `THIRD-PARTY.md`) is a way of editing the same Markdown: the text is parsed into the editor's model on opening and written back by a Markdown writer on every save. Where Markdown cannot keep a block exactly, the block is saved as typed and the page says so once. The choice between the Markdown box and the editor is the person's, kept in the browser, not in the document. The bundle is modified in two ways: one source key is renamed (`tableRole` to `gridRole`) and one export aliased (`tableEditing` also exported as `gridEditing`), so module code can use both; the recipe is in `THIRD-PARTY.md`. A grid in the editor is limited to 200 rows and 20 columns, the same bound as the reader; **Tab** in the last cell adds a row up to the limit.

**Paper.** The document's `layout` is `fluid` (one continuous sheet) or `paper` (pages of `pageSize`, Letter at 8.5 by 11 inches or A4 at 210 by 297 millimetres, with a 1 inch margin). Nothing about where a page breaks is stored. In reading, the blocks are laid out once in a hidden box as wide as a page's text and cut into pages from their drawn heights (`s-pages`); a manual break is a line in the text (`DL_PAGE_BREAK_LINE`). In the rich editor, `t-editor-pages` adds spacer decorations where a page ends, so the page look holds while typing; the Markdown box is not paged. Below 60 percent of a page's width (`DL_PAGE_FLOOR`, with an 8 pixel hysteresis, `DL_PAGE_HYST`) a Paper sheet is drawn as Fluid. A document of more than 6000 blocks (`PAGES_MAX`) is one sheet. **Fit width** scales the whole sheet (`fitPaper`), up to 200 percent; the editor does not split a grid between pages, so its page count can differ from reading's for a very large grid. Thumbnails of a Paper document are drawn as a page of its size. A manual break that is the first block of the text, with the heading above it or not, takes no height, so page one is the text and not an empty sheet (0.11.31, #802); a break after text still fills the rest of its page. The break is removed by Backspace at the start of the block after it and Delete at the end of the block before it (`dlRichKeys`).

**Paste and drop.** The rich editor takes the paste and the drop itself, before ProseMirror's handlers (`handleDOMEvents` in `p-rich-editor`), so the library's HTML reader is never reached (`transformPastedHTML` answers nothing). `dlRichClipText` takes the clipboard's `text/plain`; only when that is empty are the words of its `text/html` taken, by reading it in an inert document (`DOMParser`, with scripts, styles and templates removed, up to `DL_RICH_PASTE.htmlMax`) and keeping its text content. The text is then read as Markdown by the same reader as an opened document, so four-space or tab-indented lines are an indented code block. A drop takes `text/plain` only and ignores files. Read from the code; `check-documents-rich-editor.mjs` covers it and was not rerun for this document.

**The title bar.** Zoom out, Zoom in and the Zoom menu are `host.header` items (`host.header.set`), not toolbar items, because the editing row (Tags, the formats, Insert, the Editor and Layout switches, Page, Done) uses the toolbar's 16 entries. Insert holds Grid, Formula and Page break (the Grid group first while the caret is in a grid) and uses `host.menu.show` with `onClose` to give the keyboard back to the editor.

## The title bar's document select

Since 0.11.30 the open document's title is not drawn in the page. `documents.js` sets one `host.header` item of `kind: 'select'` (`id: 'doc-select'`; [api-module-sdk](../api/api-module-sdk.md), "The title bar") whose label is the title (the live one in a shared document) and whose menu is data: the space's documents newest change first (`d.<id>`, the open one `current`, at most 40, then a disabled "n more documents exist" line), then for a person who may write a divider with New document, Rename and Delete (ids `new`, `rename` and `delete`). A pick arrives as the `header` event `{ id: 'doc-select', value }`; the Zoom icons come as their own events (`zoom-in`, `zoom-out`, `zoom`). While a document is edited alone (the switch off) the menu holds only that document and Rename, because Done is how it is left. With co-editing on, Rename and Delete are off, with a reason in `hint`, while a document is locked by someone else. The toolbar order is Back, Tags, the formats and Insert on the left; Page, the Layout switch and the Editor switch on the right (`check-documents-title-bar.mjs`, source read). `content` is `flush` in the manifest and the page's own padding is the one 12 px gutter (`--mf-inset`) round the list, the sheet and the editor, as in every docked module (0.11.28, #777; `check-conformance.mjs` measures it).

## Print, Save as Markdown file and Open Markdown file

0.11.18, `documents-lib-u-output.js` for the rules and `outputWire` in `documents.js` for the page. Nothing here adds to the SDK. **Save as Markdown file** (a toolbar entry with `placement: 'menu'`, so it is in the title bar's menu) hands the text (`dlExportMarkdown`, the editor's unsaved text when editing) to `host.files.save` once the SDK has one (it has not yet, #469), else an in-page download link. **Print** is `host.standard.set({ print: { run } })`, offered while a document is open: `run` draws the document into `#dl-print` (a plain sheet, white with dark ink) and puts the page rules (`dlPrintRules`: Paper's size, one inch margin and the number at the foot; otherwise `@page { margin: 18mm }`) in a style in the head until the host says `printed`. **Open Markdown file** is the `+` entry `open` (`host.add.set`, only for people who can write) and a file dropped on the list: the file is read in the page (`dlFileText`: UTF-8 only, no NUL byte, at most 4 times `DL.sizeMax` bytes and then `sizeMax` characters) and made into a new document through the usual `create`. Read from the code; `check-documents-output.mjs` covers the rules and was not rerun for this document.

## Co-editing

Behind the module setting `coediting` (`module.json`, a boolean with `scope: "environment"`, default `false`; the owner sets it). Off, none of the files below runs and `host.live` is never touched. On, a document opened by a person who may write opens in a shared mode (`openCoDoc`) instead of the lock and Edit. Steps 3 to 4c of [plan-documents-coediting](../plans/plan-documents-coediting.md), built in slices: 0.11.13 (the bundle), 0.11.15 to 0.11.17 (the gate), 0.11.21 to 0.11.22 (4a: the channel), 0.11.23 to 0.11.25 (4b: the writer, the saved text, the stored state, settings that travel), 0.11.26 (4c: the lock, the editors list, read-only chrome), 0.11.27 (fixes from the hostile read). The plan's later step (on by default) is not built. The module's tests are `check-documents-coedit-*.mjs`, `check-documents-yjs-*.mjs` and `check-documents-title-bar.mjs`; the live checks in the plan's "Verify" were not rerun for this document.

- **The channel** (`u-coedit-sync`). One `host.live` topic for each document, `ydoc.<id>` (a hash form for an id that is not short and plain). Messages carry a base64 Yjs update `u`, a state vector `v` (also the presence beat, every 15 seconds), a piece `k/i/n/c` of a difference too big for one message (the manifest's `live.bytes` is 2048 and `perSecond` 30), or a leave `x`. The sender is the transport's `from`, never read from the data. A vector is answered with the difference, so one exchange repairs both ways and duplicates are harmless. Every message carries `l`, the epoch of the sender's lineage; a message from another lineage is not applied.
- **The gate** (`t-coedit-gate`). Every remote update goes through `guard.receive(update, sender)` and is applied only when it is safe: characters the editor cannot hold, list or quote nesting past the editor's, and any block that does not survive the writer's Markdown round trip are refused, so no accepted update can stop the writer saving. A sender is flagged after repeated refusals, and a missing sender is one shared sender, `unknown`, with its own budget. When a state still fails to read back, `mendForSnapshot` drops the offending block in one local transaction, and the others are told once ("A block that could not be saved was removed.").
- **The writer and saving** (`u-coedit-sync` `dlSyncElect`, `v-coedit-save`). The lowest key among the synced editors saves, a change of writer is taken only after it has stayed the same for a second, and every page that leaves saves once. A save is merge-before-write against the stored `doc:<id>` record (the record is the commit, as in "Saving and the lock") and raises `textRev`. A first page seeds the shared document from the stored text under a seed marker `ydoc:<id>:seed` written with compare-and-set, so two pages that open at once do not double the text. A page that sees a lineage other than the marker's is the stale one: it saves, then reopens (`lineage`).
- **The stored state** (`w-coedit-snapshot`). The writer keeps a copy of the Yjs state (`ydoc:<id>:<n>` chunks of up to 36,000 bytes, then the header last, by compare-and-set, naming the `textRev` it was made from) so a late joiner opens fast. A reader trusts none of it: the header, the lineage, every chunk's hash and the sizes are checked, the bytes go through the gate and are verified against the saved text, and a copy that fails is ignored and the document opens from its text. At most one copy per 45 seconds, and only while the write budget has room.
- **Settings that travel** (`x-coedit-meta`). The title, page colour, layout, page size and page numbers sit in a small shared map `meta` beside the text, checked by the gate; the writer's save reads them from it. A sixth key, `lock` (`{ by, name, at }`), is the document lock of step 4c: any editor may set it, and the gate checks only its shape, so it is a courtesy that honest pages keep and a hostile editor can bypass. One person has one edit window: a storage key `ydoc:<id>:w:<person>` held by the window that edits and renewed by it; a second window opens read only.
- **Editors and the cap.** At most eight people type in one document (`DL_SYNC.editorsMax`); the next reads along. The editors list (`dlCoEditorsList`) draws the people heard on the document. While another person is editing, the Markdown box is off.
- **The page** keeps the lock and Edit/Done of the older mode for a document opened with the switch off. A document already open keeps the mode it opened in; a change of the setting applies to the next one.

## Safety and licences

The Markdown reader builds DOM from a plain description and sets text with `textContent`; it never sets HTML from a document. Links are limited to `http`, `https`, `mailto` and `object`. The vendored library is marked 18.2.0 (MIT), used for lexing only; `modules/documents/THIRD-PARTY.md` lists each vendored piece with its licence and source, and `vendor/LICENSE.marked` is the licence file. The plan's rules bind every vendored library: only MIT, Apache-2.0, BSD, ISC or MPL-2.0, no outside service, no CDN, no telemetry. The licence, hash and outside-URL checks named in the plan are not built yet.
